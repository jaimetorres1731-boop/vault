# Vault V4.3 — repair candidate

This build changes the savings ledger to use the Web Locks API for serialized transaction mutations. Browsers without Web Locks fail closed for transaction writes, rather than risking concurrent overwrites. Cross-tab storage events refresh the main ledger. Edits detect changed/deleted records, and balance validation is performed against current storage under the lock. Negative balances, duplicate transaction IDs and impossible transaction/deployment dates are rejected by the main validator.

Standard and verified restore now check more input and attempt rollback of main records and preferences on storage failures. Verified savings-only export no longer marks a full backup. Full export includes V4.0 preferences. CSV line endings and foreground PIN timeout are corrected. Reset layout restores captured original positions.

## Important limits / unfinished verification
- This is a static source patch, not a completed browser regression test. Browser interaction, mobile layouts, storage quota failure injection, and multi-tab stress testing have NOT been verified.
- Web Locks is required for transaction saves; unsupported browsers display a save failure. Verify compatibility in your target browser.
- LocalStorage cannot provide a true multi-key atomic transaction. Rollback can itself fail when storage is unavailable; verified restore is not guaranteed all-or-nothing under every storage failure.
- Other scripts that write `vault-deployment-v3` directly (notably the countdown) still bypass the ledger lock; this needs architectural consolidation for complete cross-tab protection.
- Privacy coverage for all derived monetary widgets is not yet exhaustively verified.
- Standard and verified restores should be tested with full vs savings-only backups and concurrent tabs before using on real records.
- Keep an independent backup of your existing Vault data before deployment.
