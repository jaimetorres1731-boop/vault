# Vault V4.2 repair build — verification status

Source: uploaded vault-main (3).zip. This build is a patch to the supplied source, not a live-site deployment.

Implemented source changes:
- Transaction writes reload the latest persisted records and merge by transaction ID, preserving newer deployment settings. Failed writes restore state from storage and redraw the UI.
- Transaction deletion, editing, settings changes, and restore use separate persistence modes.
- Full backups include V4 preferences; legacy full restore and verified restore recognize optional preferences while older files remain readable.
- Newest sort explicitly sorts by descending transaction date.
- Verified restore validates real calendar dates and ignores stale file-read completions; confirm is disabled while loading.
- Service worker activation only deletes obsolete caches whose names begin with `vault-`.

Limitations and open tests:
- Multi-tab writes are merged against the latest localStorage snapshot. localStorage offers no atomic compare-and-swap, so truly simultaneous cross-tab read/write collisions are not guaranteed to be eliminated. A transactional IndexedDB redesign would be required for a strict guarantee.
- Static JavaScript syntax checks passed. Live browser/PIN/PDF/download/offline/mobile testing was not performed in this environment; items 9–14 and browser-specific scenarios for 1–8 remain open.
- Full JSON backup is not encrypted; PIN is intentionally not included.
- Verify on a test profile with a backup before replacing the live deployment.
